# 内蔵SoundFontのMDR同期対策

## 状態と範囲

`962cb01`（前回の終了処理修正）を起点にした変更。UIのレイアウト・折りたたみ構成は維持した。今回の作業は遅延対策の実装・検証とGitへの保存までで、Cloudflare本番へのデプロイは含まない。

対象は内蔵SoundFontとOPM/PCMを併用するMDR。ユーザー指定のMEGALITHとGeneralUser-GS.sf2を中心に検証した。ファイルはローカルChromeまたはローカルWASMで使用し、外部へアップロードしていない。

**通常負荷での全曲再生と、変換時計の累積差の改善は確認できた。ただし、ユーザー申告の「MIDIが徐々に遅れる」現象を実発音で完全再現・解消したという結論ではない。** 高負荷時の一時的な予約時刻の揺れは残っている。

## 実装したこと

1. MIDIイベントの計算用時計を125 kHzへ変更。Timer-Bの全256値でtickが整数になり、tickごとの端数切捨てと整合する累積速度差を回避する。音声出力とOPMコアのサンプルレートは変更しない。
2. OPM/PCMの出力フレーム数を整数で加算し、各ブロックの報告された再生予定時刻へMIDIを対応付ける。UIタイマーが来るたびに生のMXDRVカウンターから予約時刻を作り直さない。
3. SoundFont側に取消可能な先行予約キューを追加。OPMが描画済みの区間だけを先に渡し、AudioWorklet側で期限に合わせて適用する。まだ描画していないOPMの未来へは進めない。
4. 停止・曲の交換時に予約を世代ごと破棄。ミュートは対象トラックの予約音を破棄し、他トラック全体を停止しない。鍵盤表示も同じ取消を反映する。
5. OPMが先に終了した場合、最後の出力ブロックからMIDIの時計を継続する。最終MIDIイベントと余韻、OPM最終ブロックの排出を待つ既存の終了処理を維持する。
6. 予約音の破棄を避けるため、MDR/MDX再生中のSoundFont交換は停止後に行うよう案内する。読込中に再生が始まった場合も、新しく準備した音源だけを破棄し、現在の音源・予約を維持する。

SpessaSynthの元の圧縮済みファイルやWASMは書き換えていない。固定バージョンの配布ソースマップから元のWorklet実装を組み込み、その周囲にアプリ所有のキューを追加した。バージョン・ソースマップハッシュが異なる場合はビルドを失敗させる。ビルド方法とライセンスは `client/worklets/README.md` に記載。

## 検証結果

### MEGALITHの全曲再生

Chrome、内蔵GeneralUser-GS、安定重視プロファイル、手動発音補正0 ms。

| 出力 | 終了まで | MIDIイベント | 順序逆転・送信漏れ | 自然終了通知 |
|---|---:|---:|---:|---:|
| 48 kHz | 313.077秒 | 41,489件送信 | 0件 | 1回 |
| 44.1 kHz | 313.092秒 | 41,489件送信・Worklet適用 | 0件 | 1回 |

両方でOPM/PCMの終了を検出し、MIDI出力の非ゼロ信号を確認。ブラウザー例外は0件。MIDIノートオンは13,223件。

予定時刻と独立に記録したOPMブロックの報告時刻との残差は浮動小数点誤差程度だった。ただし両方ともブラウザーの `playbackTime` を基準にしており、独立した音響測定ではない。

44.1 kHzの全曲ではWorkletの最終適用数41,489、待機数0、通常の128フレーム単位を超える適用遅れ0件。最大適用差は2.901 msで、128 / 44100秒以内だった。48 kHzの最初の全曲測定は自然終了時の統計リセットで適用カウンターを保存し損ねたため、全曲の適用数確認には44.1 kHzの再検証結果を用いる。検証スクリプトは終了前の最終統計を保持するよう修正済み。

旧版 `962cb01` の48 kHz・90秒比較では、報告OPMブロックに対する予約残差は−36.3〜+40.0 ms、p95は+14.3 msだった。新方式の通常負荷90秒では同残差は丸め誤差程度。この比較だけで音響的な累積遅延の改善を断定しない。

### MIDI変換時計の10分比較

同じ旋律を持つPRIN_GSのOPM AとMIDI aを、128フレーム単位の生のOPMキー状態で照合した。ブラウザー・SoundFont・音声デバイスは介在しない。

- 3,616ノートの音階順が一致し、MIDIイベント内容・順序のハッシュも変更前後で一致。
- 旧48 kHz抽出では約49.95 ms/分の速度差、10分で約0.5秒の差の増加があった。
- 125 kHz抽出では傾き約−0.00024 ms/分。差の変動幅2.645 msは、観測分解能2.667 ms以内だった。
- 固定の開始差約15.66 msは残る。音色のアタック差とは別。
- この検証で旧MIDIはOPMより徐々に**先行**しており、申告された遅れとは方向が逆。独立した時刻計算の問題を改善したもので、申告の全原因を特定したとはいえない。

詳しい数値・方法・WASMの対応レート検証は `notes/midi-clock-core-audit-2026-09-08.md`。

### 停止・終了と非同期操作

- 実Chromeで、未来のノートを予約してから停止すると適用数0・待機数0。停止後に到着する旧世代のメッセージも適用されなかった。
- 続けて新世代へ送ったノートオン・オフ2件は正常に適用された。
- `song.mdr` + `sample.pdx` はdesktop/mobile双方で576件を送信し、自然終了1回。OPM終了後もMIDIイベントの送信が継続し、最終MIDI時刻26.363904秒の後、約1.50秒の余韻を待った。
- SF準備中に再生開始する競合、停止中のSF交換、ミュート後すぐ解除したときの鍵盤表示を自動テストに追加した。

## 残る制約：重負荷時の短い揺れ

1秒ごとにメインスレッドを100 ms止めるMEGALITH・90秒の負荷試験では、11,366イベントに送信漏れ・順序逆転はなかった。ただし、報告OPM時刻から予約時刻を順序保護のために寄せる一時差が最大73.195 ms発生した。p95は丸め誤差程度で、曲末側へ累積する形ではなかった。

20秒の追加測定では、隣接OPMブロックの報告時刻に最大約88 msの重なりを観測した。例えば元の予約時刻1.803115秒が、直前イベントとの順序を守るため1.870976秒へ寄せられ、差67.861 msとなった。後の予約時刻すべてへ差を加算する処理ではない。

調査したChromium実装では、`playbackTime` はメインスレッド上でイベントを実行する時点のフレーム番号から算出される。このため、遅れたコールバックの報告値を実際のPCM消費時刻だとみなすことはできない。今回の重なりという観測と整合するが、調査したソースの挙動からの推論であり、実PCM波形による確認はまだ行っていない。[Chromium実装](https://chromium.googlesource.com/chromium/src/+/acca47dc0a9e6971232cf29c4482cc410740f278/third_party/blink/renderer/modules/webaudio/script_processor_handler.cc)

Worklet統計は**順序保護後の予約時刻からの適用差**であって、元の曲内時刻やOPMの実発音との差ではない。そこでUIの診断は「GS MIDI / dispatch delay」とし、その数値をSoundFontの自動発音補正へ変換しない。手動補正・保存済みのBank別設定は残し、基準の推奨値は0 msにした。

OPM/PCMは引き続きScriptProcessorで描画する。負荷時の厳密な同期保証には、識別付きPCMブロックを音声スレッドで観測する追加測定、その後OPM/PCMとMIDIを共通のAudioWorklet出力フレームへ統一する等の次段階が必要。今回、根拠なくブロック時刻を後ろへ固定し続ける補正は加えていない。

実際のSoundFontアタック、Windows/Safari、他のSoundFontや出力デバイス、バックグラウンド状態は未検証。全環境での無音・音切れ・音ズレの完全解消は保証しない。

```sh
pnpm test

pnpm check:cloudflare
pnpm build:cloudflare

MDR_CLOCK_SOURCE='/Users/awed/Downloads/mdr/PRIN_GS.MDR' node scripts/verify-mdr-timing-clock.mjs

MDR_SYNC_SOURCE='/Users/awed/Downloads/mdr/MEGALITH.MDR' \
MDR_SYNC_PDX='/Users/awed/Downloads/mdr/MEGALITH.PDX' \
MDR_SYNC_SOUNDFONT='/Users/awed/Downloads/GeneralUser-GS.sf2' \
MDR_SYNC_SECONDS=325 MDR_SYNC_SAMPLE_RATE=44100 MDR_SYNC_MAX_P95_MS=3 \
node scripts/verify-mdr-frame-sync.mjs
```

負荷試験は `MDR_SYNC_SECONDS=90 MDR_SYNC_STALL_MS=100 MDR_SYNC_STALL_EVERY_MS=1000`。停止後の予約取消を実Workletで確認する場合は `MDR_SYNC_CHECK_CANCEL=1` を追加する。旧版は `--baseline` で比較できる。

自動テスト154件、アプリとCloudflareの型検査、Cloudflare用ビルドはすべて成功した。ビルドには既存の大きいチャンク警告とNodeの非推奨API警告が残る。
