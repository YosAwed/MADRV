# 再生位置シークの開発・第1段階

開発ブランチ: `codex/playback-seek`。開始点は `main` の `97c5fcf`。本番へのデプロイ、リモートへのpushは実施しない。

## 実装範囲

- MDX、およびMIDIトラックも抽出MIDIイベントもないMDRの再生中に位置移動できる。
- クリック／ドラッグは離した位置で1回だけシーク。ドラッグ中は移動先の時刻・割合を表示する。左右キーは5秒単位、Home／Endは周回の先頭／末尾。移動中はSEEKING表示、停止で中止できる。
- 曲とPDXを再読込し、計測を終えてから元のループ回数でコアを開始。指定位置まで通常のFM／PCMレンダリングを行い、音声を出力せずに捨てる。発音途中の状態やPCM読出し位置を進めたコアを、そのまま音声出力へ接続する。
- 2,048フレーム単位で進め、約8msの処理ごとにイベントループへ制御を返す。停止・曲変更で世代が変わったら、コアに再び触れる前に中止する。音声バッファ全体やチェックポイントは保存しない。
- 再生位置は現在表示中の周回内。完了済みの周回を含めた絶対位置へ変換するため、有限ループの回数をリセットしない。MDXのイントロを含む初回と2周目以降は、1回／2回の時間計測差から表示時間を分ける。
- ミュートを維持し、古い表示コールバック・終了タイマーを破棄する。MDXの最終ブロックは出力予定時刻まで待って自然終了する。

MIDIを含むMDRとMMLは位置表示のみ。停止中の任意位置指定も今回の対象外。内部の直接再生APIにもMIDI付きシークを拒否するガードがある。

## 検証

- Vitest: 193テスト／17ファイル成功。
- 通常とCloudflare向けの型チェック、Cloudflare向けビルド、`git diff --check` 成功。既存のビルドサイズ警告あり。
- `HECTOR87.MDX`＋`HECTOR87.PDX`をローカルで使用。1回／2回再生の各3地点で、通常の128フレーム描画とシーク後の4,096フレーム×左右の波形を比較。6地点すべてで8,192サンプルが完全一致（48kHz）。
- このMacで約58.7秒地点まで492ms、約112.5秒地点まで939ms。1曲の測定値であり、他の曲・端末・長時間ループの性能保証ではない。
- Chrome実AudioContextでMDXのドラッグ確定、5秒戻し、Home、End後の自然終了、移動中の停止を確認。1280px幅と390px幅の両方で成功。モバイル実機／Safariの検証ではない。
- `PRIN_GS.MDR`からMIDIトラックを除いた一時的な検証用コピーでも同じブラウザ検査に成功。OPM 8トラック、MIDI 0トラック、実WASMからの抽出イベント数0。元ファイルは変更せず、派生ファイルもリポジトリへ含めていない。
- シーク後の残り時間、イントロと周回長の差、ミュート保持、移動準備中のSTOP、旧音声コールバックの無音化、MIDI付きシーク拒否、最終音声ブロックの待機は自動テストでも検証。

再実行例:

```sh
node scripts/verify-playback-seek-wasm.mjs /path/to/song.mdx /path/to/bank.pdx
pnpm exec vite --host 127.0.0.1 --port 5173
node scripts/verify-playback-seek-browser.mjs /path/to/song.mdx /path/to/bank.pdx
MADRV_MOBILE=1 node scripts/verify-playback-seek-browser.mjs /path/to/song.mdx /path/to/bank.pdx
```

ブラウザ検査の`CHROME_PATH`と`MADRV_E2E_BASE_URL`は変更可能。検証用計測はViteの開発モジュールに対して行う。Vite開発サーバーは既存のpublic内の動的mjs importを拒否するため、検証スクリプトでは同じ配布ファイルを静的応答として返している。手動で試す場合はビルド後の`pnpm exec vite preview --host 127.0.0.1 --port 5174`を使う。

## 次の段階

1. MIDIのBank／Program／CC／RPN／NRPN／SysExを時系列順に復元する処理と、移動先で鳴っているノートの扱いを設計・検証する。
2. 内蔵SoundFontの予約破棄・状態復元とOPM／PCMの再開時刻を共通化する。長音・サステイン・ポルタメント・残響について、設定復元と音声状態の完全復元を区別する。
3. 外部MIDIは未送信予約の取消し、消音、設定の再送と実機の処理待ちを検証してから有効にする。実機内部の波形位置・残響の完全復元は保証しない。
4. 長時間の曲／無限ループでは先頭からの処理量が増えるため、必要に応じて状態保存やWorkerを検討する。既存WASMの`_mdx_player_seek`は公開されているが、引数・復元仕様を確定できていないため使用していない。
