# ハイブリッドMDRの終了処理を補完

2026-09-08。対象は退避していた終了対策の最新版への移植。UI、再生中の同期補正、ループ周期計算には手を加えていない。本番へのデプロイは未実施。旧変更のstashも保持している。

## 変更点

- OPM/PCMの終了フラグを検知した後、最後の曲内位置を基点にAudioContextの時計で残りのMIDIを進める。旧対策の単純な時計切替と異なり、蓄積した時計差の分だけ先へ飛ぶことを避ける。
- 再生位置表示もOPM/PCM終了後に止まらず進める。表示レイアウトは変更しない。
- MIDIの予約完了と再生終了を分離する。未送信キュー、順序維持のため補正された予約時刻、既にWorkletへ送った未来イベント、遅れて送ったイベントの実際の送信予定時刻を待つ。
- 最後のMIDIイベントから1.5秒の余韻を待つ。既存の曲長推定で用いる値と共通化した固定時間であり、全音色の実際の無音を検出するものではない。
- OPM/PCMが最後のブロックを生成した直後に切断せず、そのブロックの再生予定時刻＋ブロック長まで待つ。後続の無音ブロックでは終了時刻を更新しない。
- 有限ループの終了境界と安全タイマーは維持しつつ、既知のMIDI予約や余韻を途中で切らないようにした。手動停止は即時停止を維持し、旧世代の終了通知は発火させない。

## ブラウザでの回帰検証

ローカルChromeの実AudioContext／SoundFontで検証。ファイルは外部へアップロードせず、127.0.0.1だけで配信した。

- MDR: ユーザー提供 `song.mdr`
- PDX: ユーザー提供 `sample.pdx`
- SoundFont: ローカル `GeneralUser-GS.sf2`
- MIDIイベント数: 576、譜面上の最終イベント26.3225秒、表示曲長27.8225秒。

| コード／設定 | 送信MIDI数 | 自然終了時刻※ | 最終送信予定時刻から終了まで | 終了通知 |
| --- | ---: | ---: | ---: | ---: |
| 修正前32597e5／desktop | 574 / 576 | 26.168秒 | −0.011秒 | 1回 |
| 修正後／desktop | 576 / 576 | 27.819秒 | 1.514秒 | 1回 |
| 修正後／mobile（安定優先） | 576 / 576 | 27.749秒 | 1.505秒 | 1回 |

※タイムラインの開始予定時刻からの実AudioContext経過時間。既存の音源補正やブロック単位の時計により、表示曲長や設定間の値と完全には一致しない。

修正前は最後の2イベントが未送信のまま終了した。また、最後に送信したイベントにも終了時点では未来の予約が残っていた。比較モードの回帰検査が失敗することで、早期停止を再現できた。

修正後はOPM/PCM終了フラグ検知後のMIDI出力も非ゼロ（MIDIバス最大値desktop 0.280、mobile 0.285）。終了後の表示は曲長に一致し、ブラウザ例外なし。これは末尾の再生継続・終了待機の検証であり、長時間の累積遅延や厳密なサンプル単位の発音同期の保証ではない。

再実行例（実際のファイル位置に置き換える）:

```sh
MDR_END_SOURCE=/path/to/song.mdr MDR_END_PDX=/path/to/sample.pdx MDR_END_SOUNDFONT=/path/to/GeneralUser-GS.sf2 node scripts/verify-mdr-trailing-midi.mjs
```

`--baseline` を付けると修正前32597e5で同じ検査を行う。この曲では早期停止を検出して失敗することを確認した。
